# v0.3 backlog

Issues found during the review of v0.2.0 that are outside the v0.2.0 scope. v0.2.0 is closed for new
features; new findings are added here.

## Methods

- **Read-end counting for APA and TSS promoters.** PAS and TSS usage are computed from the read counts
  Bambu assigns to transcript models, so only end differences between transcript models are seen; tandem
  APA (isoforms differing only in 3' UTR length) is largely not detected (README, APA limitation). Plan:
  count the 3'/5' ends of primary alignments per PAS/TSS cluster (as LAPA or IsoQuant do), with the
  transcript-based counts as a fallback.
- **DEXSeq usage tests: one model per run.** `bin/usage_dexseq.R` fits each comparison on its two
  conditions only. Fitting all samples once (dispersions from all replicates) and testing each contrast
  would keep more residual degrees of freedom with several conditions.
- **SUPPA2 expression filter.** PSI is computed from read counts, so `psiPerEvent -f <min reads>` and
  `diffSplice -l <min dPSI>` would remove low-count events and the p = 0 artefacts at dPSI ≈ 0.
- **TE counts are not independent features.** In exon mode every read of a transcript counts for each TE
  it contains, so TE counts follow host-transcript expression (UTR Alu/MIR elements). Document this in
  the README and consider host-gene-adjusted results or separate annotated/novel host transcripts.
- **`tss` promoters:** size factors with `type = "poscounts"` (the default ratio method fails when every
  gene has a zero in some sample); Major/Minor ties are resolved by genomic order; the activity threshold
  0.25 on log2(count + 1) makes a promoter with a single read in one replicate "Minor".
- **proActiv** does not model design covariates (a warning is printed).

## Robustness

- `bin/apa_sites.R`: a transcript of the GTF missing from the count table gives "subscript out of
  bounds" (Bambu always writes both, so this does not happen inside the pipeline).
- `bin/apa_summary.R`: the top PAS is the one with the largest |dPAU| whether or not it is significant.
- `alternative_promoters.tsv` of the `tss` method has only a `Message` header when the test was not run.
- IsoformSwitchAnalyzeR: errors of `extractSequence`/`analyzeSwitchConsequences` are reported as "no
  switches"; write the error text instead. In IsoformSwitchAnalyzeR 2.6.0, `addORFfromGTF(quiet = TRUE)`
  and `analyzeNovelIsoformORF(quiet = TRUE)` return NULL (the pipeline uses `quiet = FALSE`); report
  upstream.
- `bin/te_analysis.sh`: exons are ranked by transcript ID only (a transcript ID reused on another
  chromosome would mix exons; not seen with Bambu output); span-mode sums ≥ 1e6 print in exponent
  notation (use `%.10g`).
- `collect(sort: true)` for the BAM and junction lists passed to BAMBU and TE_ANALYSIS, so that the
  task hash does not depend on the order in which samples finish (resumed runs have cached them so far).

## Pipeline structure and resources

- Split `main.nf` into subworkflows (input/preparation, quantification, downstream analyses, QC) and move
  publishing to a workflow `output {}` block.
- `MINIMAP2_ALIGN` runs `minimap2 -t <cpus>` plus `samtools sort -@ 4` on `<cpus>` CPUs; `EXTRACT_JUNCTIONS`
  could use `samtools view -@`; the read-name length check after alignment repeats the check done before
  it; `GTF_INTRONS` reports the samtools version although it only uses awk.
- The test profile sets `process.resourceLimits` directly, which overrides `--max_*` on the command line.
- SQANTI3: publish the corrected GTF/FASTA and parameter file; files named in `--sqanti3_args` (e.g.
  `--CAGE_peak`) are not staged into the task (under Docker they must be on a mounted path).
- `MULTIQC.out.versions` is not used (the MultiQC version is recorded by `SOFTWARE_VERSIONS`).
- CI: stub runs could run without containers (they only need coreutils and awk), which would save the
  image downloads; add stub runs for `--promoter_method tss` and BAM input.

## Checked, no change needed

- BAM input under Docker: downstream tasks receive the original BAM path (Nextflow resolves the
  symbolic link created by `SAMTOOLS_INDEX`), so no dangling links occur; a Docker run with BAMs outside
  the launch and work directories is part of the manual CI job.
